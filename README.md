# Employee Management System (EMS)

This project is a full-stack employee management system built with a React + TypeScript frontend and an Express + TypeScript backend. It is designed to help teams manage employees, departments, leave requests, and dashboard analytics in a practical HR workflow.

It is used to control and monitor employee records and operations across the organization.

## Stack

- Frontend: React, Vite, TypeScript, React Router
- Styling: Tailwind CSS and reusable UI patterns
- Backend: Node.js, TypeScript, Express
- Database: MySQL 8 with Prisma ORM
- Auth: JWT + secure HTTP-only cookies with CSRF protection

## Quick start

1. Copy the example environment files:
   - `backend/.env.example` -> `backend/.env`
   - `frontend/.env.example` -> `frontend/.env`
2. Start MySQL locally with Docker:
   - `docker compose up -d mysql`
3. Apply Prisma schema to MySQL:
   - `cd backend`
   - `npm run db:push`
   - `npm run db:seed`
4. Start the backend:
   - `npm run dev`
5. Start the frontend in a second terminal:
   - `cd frontend`
   - `npm run dev -- --host 0.0.0.0`

## Beginner-friendly notes

- The frontend manages screens and user experience.
- The backend acts as the business rule layer and enforces access control.
- Prisma gives you a type-safe database layer and makes schema changes easier to review.
- JWT tokens are stored in secure cookies, while a CSRF token protects state-changing actions.
- We keep secrets in environment files instead of checking them into source control.

## Security and limitations

The dashboard, employee, department, and leave-request APIs now persist through Prisma/MySQL. Employee identifiers are generated by the API when omitted, list endpoints are paginated (up to 100 records per page), and writes are validated and recorded in the audit table. Employees are limited to their own records and department managers to their department; HR managers and admins can manage organization-wide records.

The demo seed is idempotent and refuses to run when `NODE_ENV=production`. Demo credentials are prefilled and shown only in Vite development mode. Production startup requires explicit `DATABASE_URL`, `CLIENT_URL`, and a unique `JWT_SECRET` of at least 32 characters. The health endpoint checks database connectivity.

This is not yet a production-complete HRMS. Payroll, attendance, recruitment, performance reviews, document/file management, employee notifications, PDF/XLSX exports, and a production migration history are not implemented. `prisma db push` is for local development only; introduce and review Prisma migrations before deploying schema changes to production. Add integration tests and complete a security/compliance review for the target hosting environment before using real employee data.
